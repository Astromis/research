# Translation via LLM

**Скрипт: `src/translation_via_llm.py`**  
Скрипт предназначен для перевода датасета с использованием больших языковых моделей. Также поддерживается разбиение данных на батчи и логирование всех операций. Скрипт обрабатывает датасет в формате HF из заданной директории и переводит каждое предложение на русский язык с помощью LLM, а затем записывает результаты в новый HF файл датасета.

## Запуск скрипта

Скрипт можно запустить из командной строки, передавая следующие аргументы:

1. **--config** (опционально):  
* Указывает путь к конфигурационному файлу модели (JSON)  
* Дефолтное значение:references/model_config.json ; - Но обязательно нужно заменить содержимое файла, т.к там указаны заглушки  
* Конфигурационный файл должен содержать след. поля: base_url,api_key, model

	`--config config.json`

2. **--system_message** (опционально):  
* Указывает путь к файлу с системным сообщением для модели.  
* Дефолтное значение: references/system_message_translation_via_llm_2.txt

	`--system_message system_message.txt`

3. **--input_dataset** (обязательно):  
* Путь к входному датасету (JSON-файл).

	`--input_dataset datasets/test.json`

4. **--examples** (опционально):  
* Указывает путь к JSON-файлу с примерами ввода и вывода для использования в промпте.  
* Дефолтное значение: references/model_examples_translation_via_llm.json

	`--examples ref/examples.json`

5. **--batch_size** (опционально):  
* Размер батча для обработки датасета. Если 0 (или если аргумент не передается), данные обрабатываются целиком.  
* Дефолтное значение: 0

	`--batch_size 5`

6. **--proc_cnt** (опционально):  
* Количество процессов для многопроцессорной обработки датасета.  
* Дефолтное значение: 1  
* Распараллеливание настроено по батчам, т.е. обязателен параметр –batch_size

	`--proc_cnt 5`

7. **--save_intermediate** (опционально):  
* Указывает нужно ли сохранять промежуточные результаты (необработанные файлы полученные моделью). Если аргумент указан, нужно передать путь для сохранения промежуточных результатов.  
* Дефолтное значение: temp_model_result.json

	`--save_intermediate datasets/test_result_raw.json`

8. **--output_result** (опционально):  
* Путь для сохранения итоговых результатов.  
* Дефолтное значение: translation_result.json

	 `--output_result datasets/test_result.json`

9. **--process_failed_indexes** (опционально):  
* Повторная обработка элементов датасета, которые LLM вернула с ошибкой. В параметре передается путь к файлу с идентификаторами.

	 `--process_failed_indexes my_failed_indexes.txt`

10. **--postprocessing_only** (опционально):  
* Флаг для выполнения постпроцессинга по результатам работы взаимодействия с LLM.  
* Если были сохранены промежуточные результаты (необработанные файлы полученные моделью, --save_intermediate), то будет выполнено их формирование в итоговые результаты (--output_result) по оригинальной последовательности датасета (--input_dataset)  
* Пример случая для использования:  
  * Производилась обработка датасета из 1000 примеров, 15 примеров завершились с ошибкой.  
  * Эти 15 примеров повторно отправляем в обработку моделью и получаем промежуточные результаты (необработанные файлы полученные моделью).   
  * Объединяем их с промежуточными результатами после первого прогона (где находится 985 результатов)  
  * Запускаем постпроцессинг и получаем готовый перенесенный/переведенный датасет из 1000 примеров.

	 `--postprocessing_only`

Скрипт можно запустить из командной строки, передавая аргументы. Пример:  
`python src/translation_via_llm.py --config config.json --input_dataset datasets/test.json --examples ref/examples.json --save_intermediate datasets/test_result_raw.json --output_result datasets/test_result.json --batch_size 100`

## Адаптация скрипта к изменениям задачи

При сохранении той же задачи (перевод предложений, структура датасета) менять ничего не нужно либо возможно изменение след. файлов:

* **Примеров** (`examples`), переданных в скрипт через аргумент `--examples`. Примеры можно корректировать для адаптации к новым данным.  
* **Системного сообщения** (`system_message`), которое задается через аргумент `--system_message`.  
* **Модели**, параметры которой настраиваются через файл конфигурации, передаваемый в `--config`.

Если меняется задача (например, изменяется формат данных или добавляется другая логика), потребуется не только обновить вышеуказанные файлы, но и:

* **Логику проверки правильности формата выходных данных**  
* **Необходимо будет обновить структуру (интерфейс) `ResultSchema` для проверки новых полей или измененного формата данных.**

## Формат выходных данных и файлы, создаваемые скриптом

После завершения работы скрипта формируются следующие файлы:

1. **Логи**:  
   * Записываются в .log файл (например, `model_run_translation_YYYY-MM-DD_HH-MM-SS.log`), включая информацию об успешных/неуспешных операциях и возможных ошибках  
2. **Файл с ошибками**:  
   * Если модель не проходит валидацию три раза, соответствующий идентификатор записывается в `failed_indexes.txt`  
3. **Итоговые результаты**:  
   * Сохраняются в файл, указанный в аргументе `--output_result` (по умолчанию `result.json`)  
4. **Промежуточные результаты**:  
   * Если передан флаг `--save_intermediate`, результаты обрабатываются и сохраняются в указанный файл (по умолчанию `temp_model_result.json`)  
5. **Разбитые батч-файлы**:  
   * Если в аргументе `--batch_size` задано значение больше 0, датасет разбивается на батчи, которые сохраняются в директорию (по умолчанию `batches/`)  
6. **Результаты батчей**:  
   * При активации батчинга промежуточные результаты обработки каждого батча сохраняются в директорию (по умолчанию `batches_res/`)
